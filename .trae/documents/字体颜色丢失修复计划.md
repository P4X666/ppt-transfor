# 字体颜色丢失修复计划

## 摘要

用户反馈：PPT 文字颜色未正确获取，导致转换后的 PPT 背景黑、字体也黑，文字无法显示。

通过调试定位到根因：**普通文本框（TEXT_BOX）的字体颜色来自 `<a:txBody>/<a:lstStyle>/<a:lvl1pPr>/<a:defRPr>/<a:solidFill>`，当前解析器完全没有读取 shape 级别的 `lstStyle`**，仅读取 run.font.color。当 run 级别没有显式颜色时，JSON 中 font_color 为 None，渲染时不设置颜色，PowerPoint 默认黑色，导致黑底黑字。

本计划修复 shape 级别默认文本样式（lstStyle）的解析，并正确透传给段落/run。

## 当前状态分析

### 根因定位

1. **普通文本框不是 placeholder**
   - 调试显示 cover_ending_page.pptx 中名字为 "INSERT TITLE" 的形状被 python-pptx 识别为 `TEXT_BOX`，`is_placeholder=False`
   - 因此 `parser/shape.py` 中 `resolve_placeholder_props(shape, slide, prs)` 不会被调用
   - `parse_text_frame(shape.text_frame, prs, inherited_props)` 的 `inherited_props=None`

2. **run.font.color 为 None**
   - 调试显示所有 title 文本的 `run.font.color.type=None`、`rgb=None`、`theme=None`
   - `_parse_font` 中 `parse_color(font.color, prs)` 返回 None
   - `inherited_props` 也为 None，最终 `model.color=None`

3. **shape 的 txBody 有 lstStyle**
   - 调试显示每个 title 的 txBody 都有 `<a:lstStyle>` 元素
   - 里面定义了默认段落属性（pPr algn）和默认字体属性（defRPr 字号/颜色/字体名）
   - 当前代码没有读取这个 lstStyle

4. **渲染时不设置颜色 → 默认黑色**
   - `renderer/text.py` 的 `_apply_font`：当 `font.color is None` 时不设置
   - PowerPoint 默认字体颜色为黑色
   - 加上背景色也是黑色，导致文字不可见

### 相关代码

- `src/ppt_transfor/parser/text.py`：`_parse_font`、`parse_paragraph`、`parse_text_frame`
- `src/ppt_transfor/utils/inheritance.py`：`_extract_defRPr_from_xml`（类似逻辑可复用）、`_extract_alignment_from_xml`
- `src/ppt_transfor/parser/shape.py`：`parse_shape` 分发到 `parse_text_frame`

## 修复方案

### 修复 1：新增 txBody lstStyle 默认属性提取函数

**新增位置**：`src/ppt_transfor/utils/inheritance.py`（因为已有类似逻辑）或 `src/ppt_transfor/parser/text.py`

建议放在 `inheritance.py`，命名为 `extract_txbody_default_props(tx_body_element, prs=None)`，因为：
- 与 `_extract_defRPr_from_xml`、`_extract_alignment_from_xml` 属于同一类 XML 解析逻辑
- 函数职责是从 XML 提取默认文本属性，与 inheritance 主题一致

**函数实现要点**：

```python
def extract_txbody_default_props(tx_body_element, prs=None) -> dict:
    """从 <a:txBody>/<a:lstStyle> 提取默认文本属性。

    返回 {
        "alignment": str|None,
        "font_size": int|None,
        "font_color": Color|None,
        "font_name": str|None,
    }

    当前先处理 lvl1pPr（大多数文本框只有一级），后续可按 para.level 扩展。
    """
```

逻辑复用：
- 查找 `<a:txBody>/<a:lstStyle>/<a:lvl1pPr>`
- 对齐：复用 `_extract_alignment_from_xml`（但当前函数从 txBody 元素查找，需确认路径）
- 字体属性：复用 `_extract_defRPr_from_xml`（直接传入 lvl1pPr 或 txBody 元素）

需要注意：
- `_extract_defRPr_from_xml` 当前查找路径是 `.//{NS_P}txBody` 然后 `lstStyle/lvl1pPr/defRPr`，所以直接传入 txBody 元素即可
- 但 shape 的 txBody 元素命名空间是 `{NS_P}txBody`，与函数兼容

### 修复 2：parse_text_frame 合并 shape-level 默认属性

**修改文件**：`src/ppt_transfor/parser/text.py`

在 `parse_text_frame` 中：
1. 提取 shape 自身 txBody 的默认属性（`shape_default_props`）
2. 与传入的 `inherited_props`（placeholder 的 layout/master 属性）合并
3. 优先级：run 显式 > paragraph 显式 > shape txBody lstStyle > layout/master placeholder lstStyle

由于当前 `parse_paragraph` 和 `_parse_font` 已经实现"显式优先、继承兜底"，合并方式：
- 先让 `shape_default_props` 作为基础
- 再用 `inherited_props` 中 shape_default_props 没有的部分补齐
- 传入 `parse_paragraph` 和 `_parse_font`

```python
def parse_text_frame(tf, prs=None, inherited_props: dict | None = None) -> Text:
    # ...
    # 提取 shape 自身 txBody 的默认属性
    from ppt_transfor.utils.inheritance import extract_txbody_default_props
    shape_defaults = extract_txbody_default_props(tf._element, prs)

    # 合并：shape 自身默认属性优先于 layout/master 继承属性
    # 因为 shape 自己的 lstStyle 通常是对 layout/master 的覆盖或明确指定
    merged_props = dict(shape_defaults)
    if inherited_props:
        for key, value in inherited_props.items():
            if merged_props.get(key) is None:
                merged_props[key] = value

    for para in tf.paragraphs:
        model.paragraphs.append(parse_paragraph(para, prs, merged_props))
```

### 修复 3：paragraph 对齐从 txBody lstStyle 兜底

**修改文件**：`src/ppt_transfor/parser/text.py`

当前 `parse_paragraph` 只读取 `para.alignment`。如果 paragraph 本身没有显式对齐，但 txBody lstStyle 有 pPr algn，应该取 txBody 的对齐。

由于 `merged_props` 中已包含 `alignment`，现有逻辑已能兜底：
```python
elif inherited_props and inherited_props.get("alignment"):
    model.alignment = inherited_props["alignment"]
```

所以修复 2 完成后，title 居中对齐也会自动修复。

### 修复 4：渲染时无颜色但背景为黑的兜底（可选）

**不优先采用**：猜测默认颜色为白色会引入更多不可控差异。正确做法是解析出原始颜色。

如果修复 1-3 后仍有部分文字颜色为 None（例如纯图片上的文本框无 lstStyle），可考虑：
- 在渲染时检测 shape 背景是否为深色，自动设为白色
- 但这属于启发式修复，应作为最后手段

## 假设与风险

### 假设
- shape 的默认文本颜色确实定义在 `<a:txBody>/<a:lstStyle>/<a:lvl1pPr>/<a:defRPr>` 中
- 多 level 文本框（lvl2pPr, lvl3pPr...）较少，可先统一用 lvl1pPr 兜底
- 原始 PPT 的 title 文本框颜色是白色/浅色，不是黑色

### 风险
- **多 level 段落**：如果文本框有 lvl2pPr 等不同级别样式，统一用 lvl1pPr 可能有偏差。可在后续按 `para.level` 扩展
- **lstStyle 与 placeholder 继承冲突**：合并顺序需确保 shape 自身默认属性优先于 layout/master。如果顺序反了，可能仍取到黑色
- **解析出的颜色仍是黑色**：如果 lstStyle 中定义的就是黑色，说明原始设计就是黑底黑字（不太可能），需要视觉确认

## 后续可选优化

- 按 paragraph level 分别提取 `lvlNpPr`（N=1,2,3...）默认属性
- 对 table cell 同样提取 txBody lstStyle 默认属性（当前 table.py 调用 parse_text_frame，可自动受益）
- 渲染器添加"无颜色且深色背景时默认白色"的启发式兜底
